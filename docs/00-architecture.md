# Архитектура контент-завода

Замкнутый цикл: завод не просто штампует ролики, а **учится на том, что зашло**.
Управляется через Google Sheets (одна строка = один ролик) по принципу
конечного автомата: каждый воркфлоу подхватывает строки в нужном `status`,
делает свою работу и переводит строку в следующий статус.

```
        ┌────────────────────────────────────────────────────┐
        │            GOOGLE SHEETS  (вкладка "queue")          │
        │            строка = ролик + статус + данные          │
        └────────────────────────────────────────────────────┘
   WF1 ТРЕНДЫ   →  WF2 СЦЕНАРИЙ →  WF3 ГЕНЕРАЦИЯ → WF4 ТЕКСТЫ → WF5 ПУБЛИКАЦИЯ
   (Cron, идеи)    (хук+шотлист)   (fal.ai→Creatomate) (captions) (upload-post)
        ▲                                                              │
        │                                                              ▼
        └────────── WF6 АНАЛИТИКА ◄──────────────────────────── ✅ published
                    (метрики → perf_score → учим тренды)
                         WF7 ДАЙДЖЕСТ (утром: что выйдет + kill-switch)
```

## Конечный автомат (поле `status`)

| status      | кто ставит | что значит                                   | дальше      |
|-------------|------------|----------------------------------------------|-------------|
| `idea`      | WF1 / руки | тема выбрана, ждёт сценария                   | → WF2       |
| `scripted`  | WF2        | есть хук + сценарий + шот-лист                | → WF3       |
| `producing` | WF3        | видео генерируется (async)                    | → WF3       |
| `produced`  | WF3 / руки | готовый MP4 лежит в `video_url`              | → WF4       |
| `queued`    | WF4        | тексты готовы, стоит `publish_at`            | → WF5       |
| `published` | WF5        | опубликовано, есть ссылки                     | → WF6       |
| `error`     | любой      | упало, смотри `error_log`                     | разбор руками|
| `skipped`   | WF7        | снято kill-switch'ем                          | —           |

### Гибрид (готовые ролики vs генерация)
- **Генерация:** строка стартует в `idea` (или `scripted`) и проходит WF2→WF3→WF4.
- **Готовый MP4:** вставляешь строку сразу со `status=produced`, `source_type=upload`
  и заполненным `video_url` — она минует WF1–WF3 и попадает сразу в WF4 (тексты).

## Модули

| WF  | Файл                         | Триггер              | Делает |
|-----|------------------------------|----------------------|--------|
| WF1 | `workflows/wf1-trends.json`  | Cron (раз в день)    | собирает тренды/идеи → пишет строки `idea` |
| WF2 | `workflows/wf2-script.json`  | Cron (скан `idea`)   | LLM: хук, сценарий, шот-лист → `scripted` |
| WF3 | `workflows/wf3-generation.json` | Cron (скан `scripted`) | fal.ai (клипы) → Creatomate (монтаж) → `produced` |
| WF4 | `workflows/wf4-captions.json`| Cron (скан `produced`)| LLM: тексты под YT/IG/Threads → `queued` |
| WF5 | `workflows/wf5-publish.json` | Cron (скан `queued`) | upload-post → 3 площадки → `published` |
| WF6 | `workflows/wf6-analytics.json`| Cron (раз в день)   | метрики → `perf_score` → фидбэк в тренды |
| WF7 | `workflows/wf7-digest.json`  | Cron + Webhook       | дайджест в Telegram + kill-switch |

## Принципы (уроки реальных заводов)

1. **Дистрибуция важнее производства.** Поэтому WF1 (тренды) и WF6 (аналитика) —
   не опция, а ядро. Завод без петли обратной связи штампует в никуда.
2. **Тяжёлое — наружу.** Генерацию видео крутит fal.ai (async + webhook), n8n только
   дирижирует. n8n плохо работает с долгими циклами.
3. **Cost guard обязателен.** AI-видео — главная статья расхода (\$1–5/ролик).
   WF3 проверяет дневной лимит `DAILY_VIDEO_BUDGET_USD` перед генерацией.
4. **Одно ДНК.** `config/channel-dna.yaml` подмешивается во все промпты —
   иначе лента превращается в безликую солянку.
